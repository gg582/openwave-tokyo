# 벤치마크 — 보수쌍(warp-shuffle) vs 전통(대조군)

모든 수치는 추정이 아니라 실제 파이프라인에서 측정한 값입니다.

## 테스트 환경

| 항목 | 값 |
|---|---|
| GPU | NVIDIA GeForce RTX 3070 (sm_86, 8.2 GB) |
| CUDA | 13.1 (드라이버 610.43) |
| GL | EGL 1.5 헤드리스, OpenGL 3.3 core |
| 인코더 | FFmpeg libavcodec 61, `h264_nvenc` (CUDA hw_frames, zero-copy) |
| 빌드 | `nvcc -O3 -std=c++17 -arch=native` |

## 1. FFT 마이크로 벤치마크 — 2D IFFT (`./hokusai_wave --bench`)

배치 1D(행) + 타일 전치 + 배치 1D(열), in-place, float2.

| 크기 | 전통 (대조군) | 보수쌍 (warp-shuffle) | 가속비 |
|---|---|---|---|
| 256 × 256   | 0.0643 ms | 0.0380 ms | **1.69×** |
| 512 × 512   | 0.1279 ms | 0.0794 ms | **1.61×** |
| 1024 × 1024 | 1.3459 ms | 0.8062 ms | **1.67×** |

수치 동등성: 두 구현 모두 256²에서 CPU DFT 참조와 최대 오차 **1.1e-9** —
차이는 순수하게 데이터 이동뿐입니다.

### 이유: 배치 1D FFT당 DRAM 트래픽 (행당 N, logN 스테이지)

| 경로 | 글로벌 메모리 원소 접근 |
|---|---|
| 전통 | 비트 반전 복사(2N) + logN 스테이지 × 2N + 결과 복사(2N) = **2N·(logN + 2)** |
| 보수쌍 | 레지스터 상주 warp 커널(2N) + (logN − 5) 교차-warp 스테이지 × 2N = **2N·(logN − 4)** |

512(logN = 9) 기준: 22N vs 10N 접근 — **2.2× 트래픽 절감**. 측정 가속이
1.6×인 이유는 두 경로가 두 번의 전치와 1/N 스케일 패스를 공유하기
때문입니다. span 1–16의 5개 스테이지(9개 중)는 보수쌍 경로에서 메모리를
전혀 건드리지 않습니다: 피연산자 `B·W`가 대척 레인 `T_i`/`T_{i+16}` 사이를
`__shfl_xor_sync`로 레지스터 레벨 (~1사이클)에서 이동하고, 덧셈/뺄셈 역할은
무분기 부호 비트 XOR로 선택되어 워프 다이버전스도 없습니다
(SASS: 버터플라이 내 SHFL 10, FSEL 50, BRA 0).

## 2. 전체 파이프라인 — 1800프레임 (60초), 1280×720 @ 30fps, 512² 해양

전체 실행에 대한 프레임당 평균:

| 단계 (ms/프레임) | 전통 | 보수쌍 |
|---|---|---|
| 해양 시뮬 (진화 + 3× 2D IFFT + 조석/쇼어링/야코비안 폼) | 0.447 | **0.356** (−20 %) |
| GL 렌더 (공유: 하늘 + 지형 + 원해 + PBR 해양 + 수차) | 0.669 | 0.669 |
| 후처리 언샤프 (동일 알고리즘; 메모리 탭 vs warp-shuffle 탭) | 0.111 | 0.137 |
| 인코드 (RGBA→NV12 + NVENC + 먹싱) | 0.095 | 0.097 |
| **합계** | **1.323** | **1.259** |

## 4. 스프레이(입자) 커널 — A/B 벤치마크

탄도 스프레이 입자 시스템의 두 동기화 커널을 매 프레임 두 변형으로
실행합니다 (출력은 비트 동일 검증):

| 커널 | 전통 | 보수쌍 (warp-shuffle) | 가속비 |
|---|---|---|---|
| 발사체 스캔 (쇄파 셀 수집) | 0.0086 ms (셀별 글로벌 atomicAdd) | 0.0065 ms (warp-ballot + shuffle 프리픽스, warp당 1 atomic) | **1.32×** |
| 그리드 투영 (폼 퇴적) | 0.0047 ms (입자별 naive atomicAdd) | 0.0045 ms (`__match_any` 리더, warp 집계) | **1.06×** |
| 탄도 업데이트 (공유) | 0.0370 ms | 0.0370 ms | — |

발사체 스캔은 작업이 조밀할수록 (warp당 셀이 많을수록) 이득이 큽니다
(32개 ballot이 소수의 atomic으로 축약). 투영은 warp당 착수 입자가
드물어 이득이 작습니다 — 집계는 같은 셀을 공유하는 레인이 있을 때만
유효하기 때문입니다. 퇴적은 Q16.16 고정소수이고 발사체 목록은 호스트
정렬이라 두 변형이 비트 동일을 유지합니다.

## 출력 동등성 (통제된 A/B)

두 파이프라인은 매 프레임 동일한 장면을 렌더링하며 비트 단위로 일치해야 합니다:

- 파도장: depth/gain/height/foam max |diff| = 0.000e+00 (60프레임마다 검사)
  — 두 FFT 구현이 비트 동일
- 프레임: 1800프레임 전체에서 **0바이트 불일치, max |delta| = 0**
- 파일: `sha256(hokusai_traditional.mp4) == sha256(hokusai_complementary.mp4)`
  — **바이너리 동일 MP4**

이에 도달하기까지 실제 버그 2개를 수정했습니다:
1. 보수쌍 warp FFT가 비트 반전 피연산자를 IN-PLACE로 gather — warp 간
   읽기/쓰기 레이스로 프레임이 비결정적으로 깨졌습니다 (눈에 보이던
   프레임 떨림의 원인). 이제 스크래치 복사본에서 gather
2. shuffle 언샤프 커널에서 lane 30의 off-warp 탭 누락
   (`__shfl_down_sync(x, 2)` 범위 이탈 시 자기 값이 반환됨) — 범위 밖
   탭은 동일 산술로 글로벌 메모리에서 계산

후처리 수치 참고: 720p에서 5탭 언샤프는 RTX 3070의 L2에 들어가므로 이
크기에서는 warp-shuffle이 더 빠르지 않습니다 (0.137 vs 0.111 ms) —
커널이 메모리 바운드가 아니기 때문입니다. 프레임당 지배적 효과는 FFT
가속 (−21 %)입니다.

두 파이프라인은 단일 프로세스에서 매 프레임 동일한 장면을 렌더링했습니다
(동일한 결정론적 스펙트럼 시드와 시뮬레이션 클럭) — 두 MP4의 콘텐츠는
동일하고 커널만 다릅니다.

**재생 시간은 물리적으로 고정됩니다**: MP4는 정확히 30fps로 재생되고,
재생 1초당 시뮬레이션 시간은 정확히 3.0초 (`--timescale`)씩 진행합니다 —
렌더링 속도와 무관합니다.

참고:

- 해양 단계 가속 (−0.12ms)은 512² FFT 차이 (변환 3회 × 각 ~0.05ms 절감)와
  일치 — 해당 단계에서 shuffle FFT가 유일한 차이입니다.
- CUDA 보정 커널은 921,600px에 0.088ms (색수차 역정렬 + 5탭 레지스터 교환
  블러 H/V + 역OTF 게인) — 60fps 프레임 예산의 ~3%.
- 보수쌍 경로의 더 선명한 출력 (주변부 에지 대비 복원)은 인코더에도
  보입니다: 동일 NVENC 품질 설정에서 `hokusai_complementary.mp4`가
  4.54MB vs 2.03MB — 고주파 디테일이 더 살아남아 부호화됨.

## 재현

```bash
cd hokusai && make
./hokusai_wave --bench
./hokusai_wave --mode complementary --frames 1800 --out hokusai_complementary.mp4
./hokusai_wave --mode traditional  --frames 1800 --out hokusai_traditional.mp4
```
